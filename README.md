# VAMP vs cuRobo on one Jetson

An apples-to-apples comparison of [VAMP](https://github.com/KavrakiLab/vamp) and cuRobo v1, run on the same board: a Jetson Orin NX 16 GB.
- **VAMP:** a CPU SIMD-vectorized RRT-Connect, running on one Cortex-A78AE core with NEON.
- **cuRobo v1:** a GPU trajectory optimizer, running on the Orin NX's Ampere GPU.

Both planners solve the same problems:
- **Standard benchmark:** VAMP's MotionBenchMaker problems for the Panda and the UR5.
- **Our paper's scenes:** the scenes from *Industrial Robot Motion Planning with GPUs: cuRobo for Extended DOF Systems* (arXiv 2508.04146). These are a UR5e on a 7th-axis rail and a fixed UR5e, in pick-and-place scenes.

**Same collision model.** Both planners check the same collision spheres against the same obstacles, and both are given joint-space start and goal configurations. On 16,000 random configurations, their collision checkers gave the same verdict 100% of the time (`results/collision_model_agreement.json`).

> **Status:** VAMP numbers are final. The cuRobo cells are **pending** a run on an idle GPU (the board's GPU is currently used by another job). A partial run made while the GPU was shared is kept in `results/raw_contended/` and is not cited.

## Headline numbers

Wall-clock time per query, measured on the same Jetson Orin NX 16 GB (MAXN). Times are over solved queries.
- VAMP time: build the environment + plan + simplify.
- cuRobo time: `update_world` + `plan_single_js`.

| Panda · MBM, 7 scenes | 699 | 699 (100%) | **1.76 ms** (3.89) | pending | pending | pending |
| UR5 · MBM, 7 scenes | 689 | 689 (100%) | **2.02 ms** (4.80) | pending | pending | pending |
| UR5e + rail · pillars (paper) | 103 × 10 seeds | 1020/1030 (99.0%) | **0.95 ms** (1.35) | pending | pending | pending |

| UR5e · pillars (paper) | 103 × 10 seeds | 1030/1030 | **0.97 ms** (1.43) | pending | pending | pending |

**How to read the VAMP column:**
- **Python overhead.** About 0.5 ms of each VAMP wall time is the Python binding and converting the environment. VAMP's own C++ timers give lower medians: Panda 1.20 ms, UR5 1.46 ms, rail/pillars 0.40 ms, rail/free 0.03 ms, UR5e/pillars 0.44 ms.
- **The one failure.** VAMP's only failures are a single gantry query (problem 64). It fails on all 10 seeds, each time after about 4.2 s, when it reaches the default iteration cap.
- **Path length** (median joint-space L2 of the simplified path): Panda 4.90 rad, UR5 6.53 rad, rail/pillars 5.34 rad, rail/free 4.56 rad, UR5e/pillars 5.99 rad.

Every number above comes from `results/summary.json`, which `bench/analyze.py` builds from the per-query records in `results/records/`.

## What is being compared, and what isn't
- **Hardware.** Both planners run on one board.
  - VAMP is single-threaded and uses 1 of the 8 CPU cores.
  - cuRobo uses the whole GPU, plus one CPU thread.
  - Since it's one board, a per-dollar comparison doesn't apply. Board power is logged for every run (`tegrastats`, in `summary.json` → `power`). A per-watt figure will be given once a clean GPU run exists.
- **Outputs differ.** cuRobo returns a smooth, time-parameterized trajectory that respects jerk limits. VAMP returns a simplified geometric path that still needs time parameterization. The timings are for each planner's standard output.
- **Settings.**
  - VAMP: library defaults (`rrtc` + `simplify`, Halton sampler), as in its own `scripts/evaluate_mbm.py`.
  - cuRobo: the settings of its own `benchmark/curobo_benchmark.py` (20 attempts, graph planner enabled, finetuning on, CUDA graphs, warmed up).
  - Neither planner was tuned.
- **Version.** cuRobo is v1 (`ebb7170`), the version the paper used, not the current v2 rewrite.

Full method, the paper-scene definitions, and the deviations from the paper's scripts: [docs/METHOD.md](docs/METHOD.md).

## Reproduce
```bash
# VAMP (isolated venv; builds on aarch64/NEON, x86 AVX2 or Apple Silicon)
git clone --recursive https://github.com/KavrakiLab/vamp third_party/vamp   # 27cb9b6
python3 -m venv .venv && .venv/bin/pip install numpy fire pyyaml tqdm pandas tabulate matplotlib
cp configs/ur5e.hh third_party/vamp/src/impl/vamp/robots/ur5e.hh            # generated by cricket fb2d081
cp configs/ur5e_rail.hh third_party/vamp/src/impl/vamp/robots/ur5erail.hh
CMAKE_BUILD_PARALLEL_LEVEL=3 .venv/bin/pip install ./third_party/vamp \
  -C cmake.define.VAMP_ROBOT_MODULES="sphere;ur5;panda;fetch;baxter;ur5e;ur5erail" \
  -C cmake.define.VAMP_ROBOT_STRUCTS="Sphere;UR5;Panda;Fetch;Baxter;UR5e;UR5eRail"
(cd third_party/vamp && ../../.venv/bin/python resources/problem_tar_to_pkl_json.py --robot panda \
  && ../../.venv/bin/python resources/problem_tar_to_pkl_json.py --robot ur5)

# cuRobo v1: see docs/CUROBO_JETSON_FIX.md for this machine's setup
bench/run_all.sh --vamp-only      # CPU
bench/run_all.sh --curobo-only    # GPU; run only when the GPU is idle
.venv/bin/python bench/analyze.py # -> results/summary.json, results/records/, results/figure.png
```
- `problems/*.pkl` holds the paper-scene problems. To regenerate them: `bench/make_paper_problems.py`.
- Sphere-model converters: `bench/spherized_to_curobo.py` and `bench/curobo_to_spherized.py`.
- Collision-model check: `bench/agreement.py`.
